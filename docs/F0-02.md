# F0-02 — Cierre único de ventas

## Reglas acordadas

- El comprador, precio final, agente y reparto de comisión son obligatorios.
- Se permite cerrar desde Captada, Publicada, En visitas, Reservada, Pendiente de
  notaría y Retirada. Una propiedad ya vendida requiere una corrección o reapertura.
- El agente puede cerrar propiedades que tiene asignadas. Los roles `MANAGER` y
  `ADMIN` pueden cerrar cualquier propiedad de su agencia.
- El agente atribuye su venta a sí mismo; el responsable puede seleccionar a un
  usuario activo de la agencia con rol `AGENT`, `MANAGER` o `ADMIN`.
- Los compradores deben ser demandantes activos accesibles en el CRM: los agentes
  seleccionan sus clientes y los responsables acceden a los de toda su agencia.
- Precio positivo, con hasta dos decimales; porcentajes entre 0 y 100, con hasta
  cuatro decimales. Un porcentaje cero es válido si se indica explícitamente.

La corrección de datos y la reapertura, con ajustes de comisiones incluso
facturadas o pagadas, están implementadas en [F0-03](F0-03.md).

## Comportamiento de la aplicación

El botón de venta de Propiedades, el selector de estado, el tablero y el registro
desde Ventas abren `SellPropertyModal`. El formulario muestra comprador, agente,
precio, porcentajes y desglose de importes. Buscar compradores y seleccionar una
propiedad en Ventas admite paginación.

Seleccionar «Vendida» o arrastrar a esa columna abre el formulario sin modificar
el estado. Cancelarlo deja la propiedad intacta. La confirmación guarda venta,
comisión pendiente y estado dentro de una única transacción. Un fallo al guardar
cualquiera de esos elementos deshace la operación completa.

El cambio de estado genérico rechaza pasar a Vendida. También rechaza salir de
Vendida: debe utilizarse la reapertura explícita de F0-03. Se mantiene la edición de
los datos de la ficha del inmueble; estos cambios no reescriben la venta histórica.

## Cálculo y trazabilidad

1. Comisión total = precio final × porcentaje sobre la venta, redondeada a céntimos.
2. Comisión del agente = comisión total × porcentaje del agente, redondeada a céntimos.
3. Comisión de la agencia = comisión total − comisión del agente.

El redondeo es `ROUND_HALF_UP`: medio céntimo se redondea hacia arriba. El backend
usa `Decimal` y el formulario calcula con enteros para mostrar el mismo resultado.
Ejemplo: 100,50 € al 1 %, repartido al 50 %, produce 1,01 € de comisión total,
0,51 € para el agente y 0,50 € para la agencia.

Cada cierre conserva los porcentajes confirmados, autor, estado de origen y fecha
de venta. No depende de cambios posteriores en las tarifas de la propiedad o del agente.

## Contrato de la API

`GET /properties/{id}/closing-options` devuelve la propiedad, agentes permitidos
y compradores accesibles. Acepta `search`, `page` y `limit` para los compradores.

`POST /properties/{id}/sell` requiere sesión y token CSRF. Ejemplo de cuerpo:

```json
{
  "request_id": "56d34aeb-489a-442f-8681-69e70c797157",
  "buyer_id": "d2c9e811-e4fd-4e88-8e35-43abced21105",
  "agent_id": "27f8665f-df7f-48b1-a8b1-b3029493e965",
  "sale_price": "200000.01",
  "commission_rate": "3",
  "agent_commission_rate": "40",
  "notes": "Condiciones confirmadas"
}
```

El formulario genera `request_id` automáticamente. Reintentar la misma solicitud
con los mismos datos devuelve la venta ya registrada y `replayed: true`.
Reutilizar el identificador con otros datos produce un conflicto `409`.
El bloqueo de la propiedad serializa los cierres simultáneos; la restricción única
por agencia e identificador protege también las solicitudes sobre propiedades distintas.
Solo el primer cierre genera notificaciones.

Una solicitud distinta sobre una propiedad ya vendida, o con una venta activa
registrada aunque su estado sea otro, produce `409`. No crea otra comisión.

## Migración e inventario

Desde `backend/`, con la configuración de la instalación:

```bash
uv sync --locked
uv run --locked python -m scripts.audit_sales
uv run --locked alembic upgrade head
```

El inventario es de solo lectura: muestra identificadores de propiedades vendidas
sin cierre activo, propiedades con varios cierres activos, ventas activas con
propiedad abierta y ventas activas sin comisión. Permite revisar esos casos antes de la actualización.

La revisión `f002a1b2c3d4` añade los campos de cierre y convierte los importes de
ventas y comisiones a `NUMERIC`. Conserva la representación decimal de los importes
históricos, incluso fracciones de céntimo. No recalcula sus repartos, rellena
compradores desconocidos, crea ventas ausentes ni elimina duplicados. Los campos
de trazabilidad de las ventas anteriores quedan vacíos cuando no se conocen.

Las nuevas operaciones aplican el redondeo descrito arriba. El rollback de la
migración elimina la nueva trazabilidad y devuelve los importes al tipo flotante;
conviene conservar una copia de la base antes de actualizar una instalación con datos.

## Verificación

```bash
# Backend: crea y elimina un contenedor PostgreSQL exclusivo para las pruebas.
cd backend
RUN_POSTGRES_TESTS=1 uv run --locked pytest

# Frontend, desde otra terminal situada en la raíz.
cd frontend
npm ci
npm test
npm run build
```

Las pruebas cubren permisos, datos obligatorios, validación de referencias,
reintentos, concurrencia, rollback ante un fallo de comisión, redondeo, consultas
económicas y actualización de datos históricos. Las pruebas del formulario
verifican cancelación, doble envío, reintento tras un fallo de red y las distintas
entradas al cierre, incluido el arrastre en el tablero.

Las pruebas de interfaz usan un DOM simulado; la inspección visual en un navegador
real queda pendiente. F0-05 y F0-06 aún requieren cobertura de los demás módulos y
su integración en las comprobaciones de entrega.

Resultado de esta entrega: 68 pruebas del backend y 21 del frontend pasan, junto
con la compilación. Se verificó además una sesión HTTP real de agente sobre una
base aislada: cierre desde Retirada, validación CSRF, reintento y listado de venta.
La migración está probada en bases desechables; queda por aplicarla a los datos de
la instalación que se quiera actualizar.
